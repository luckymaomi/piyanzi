# 一二检和副驾驶进度更新

## 报装

```
一二检和副驾驶进度更新
1. 场景：更新飞行实力表的「一二检进度」「副驾驶进度」
2. 能干：提取姓名/员工号与各人起算日期 → 填查询模板 → 收主人导出 → 核对后回填经历和起落
3. 口径：一二检取左座进入时间、左座经历；副驾驶取进入时间、飞行经历；两边均取起落总数
4. 节奏：先交查询表，等主人自行跑 CSN2API；回填先备份，异常不混写
5. 范围：一二检仅上方首块，第二表头及以下保留；副驾驶按本轮实际名单
```

## 综述

启动说法包括「更新一二检和副驾驶进度」「更新下一二检和副驾驶进度」「一二检进度更新」。这项处理实力表进度，不套用「副驾驶流转更新」积分表的排除名单和计分规则。

```
主人，皮燕子已启动，技能已加载。一二检和副驾驶进度更新，弹药在列。
先把实力表名单和各人起算日期装进查询模板，截止今天；查询表交主人去跑 CSN2API。
一二检只取上方首块，第二表头以下保留；副驾驶按本轮名单。
主人把导出结果甩回来，皮燕子核员工号、姓名和日期窗口，备份后再写经历和起落。文件以主人本轮指定为准。
```

已经给出输入路径或阶段时直接执行。缺少必要文件或名单范围有疑点时，只问缺的部分；能独立完成的结构调研、预检和副本试跑继续做。

## 输入与阶段

1. 第一步需要：原始飞行实力表、截止日期（默认上海今日）。空查询模板默认用仓内 `templates/飞行经历查询（皇帝版）-模板.xlsx`（CSN2API 皇帝版四列格式真源）；主人另指定路径时才改用外置模板。
2. 第二步需要：主人自行在 CSN2API 网页跑出的结果、本轮查询表/本轮记录、拟回填实力表路径。
3. 两步之间必须停在交付查询表；不登录、不代跑网页、不调用生产接口。
4. 主人已经说清「回填/写入」及目标文件，完成核对与备份后直接执行，不再索要同一授权。只要求调研、试跑、比对时生成根目录副本。

## 名单范围：先识别分块

以本轮实力表指定工作表的实际名单为准；不从「人员信息」另造名单，不因为技术等级过滤、不删除零经历人员。

「一二检进度」可能在同一 sheet 里有上下两块，下面再次出现「员工号/姓名/左座进入时间」表头。不能把第二表头或上下块之间空行当人员，也不能默认把下面所有历史/另一块名单一起查询。

主人已确认默认范围：一二检仅更新上方首块，第二表头及以下内容原样保留，不纳入查询或回填；副驾驶按该 sheet 实际人员名单处理。每轮按第二表头识别首块边界，人数和行号随原表变化，不固定为10人。后续沿用此范围，不重复询问；主人明确另改范围时再调整。

2026-10-23 的真实样例：副驾驶173人；一二检首块10人（第2～11行）；第14行第二表头、下方76人未查询。查询表与主人导出均183条，此范围已完成样例复现。

## 第一步：填规范查询表

格式真源：仓内 `templates/飞行经历查询（皇帝版）-模板.xlsx`。单工作表，表头仅四列且顺序固定：员工号、姓名、开始日期、结束日期。prepare 必须从该空模板（或其经主人确认的等价副本）复制生成，清掉旧人员行后再写入本轮名单，以保留模板自带的表结构与样式；不得空手新建无模板工作簿冒充查询表。

| 来源工作表 | 员工号 | 姓名 | 开始日期 | 结束日期 |
| --- | --- | --- | --- | --- |
| 副驾驶进度 | 员工号（样表A列） | 姓名（B列） | 进入时间（E列） | 上海今日 |
| 一二检进度 | 员工号（A列） | 姓名（B列） | 左座进入时间（D列） | 上海今日 |

1. 按列名识别并核验结构。样表先副驾驶、再一二检，各块内部沿用原顺序；日期用各人的起算日，不用转机型开始时间，也不用统一起算日。
2. 日期可能为真正日期、日期字符串或 Excel 日期序号（如45883）。序号按工作簿 epoch 转换，不当年月日数字，不改原表日期列。输出为真正 Excel 日期，格式 yyyy-mm-dd。
3. 员工号保留前导零；姓名按原值去首尾空白，英文姓名保留内部空格。缺工号、姓名、开始日期，日期公式无可靠缓存，或开始晚于结束，均先列异常，不补猜测值。
4. 同工号不同日期窗口属于不同查询；同工号同窗口可合并查询，但保留来源 sheet/原行号与姓名，回填时能分发到各来源行。姓名冲突须查明。
5. 以仓内空模板为底清旧行、生成本轮查询文件；仓内 `templates/` 下的空模板本身不得覆盖。记录来源文件、其 SHA256、查询表、截止日期、范围，以及每人来源行/工号/姓名/开始结束日期。跨会话读本轮记录，不能凭记忆匹配。
6. 本轮查询表、本轮记录和异常清单落在仓库根目录；空模板固定在 `templates/`；辅助脚本在 `scripts/`；本轮人员数据不写进 Skill。

交付口径：主人，查询表已按四列格式填好：副驾驶×人，一二检×人，合计×个查询窗口，截止YYYY-MM-DD。文件：〔完整路径〕。主人自行跑 CSN2API，把去分钟版导出路径发回来，皮燕子接第二步。

## 第二步：离线核验并回填

使用导出「查询结果」表的列名；以下列字母仅为样例定位，不取代列名校验。

| 目标 | 导出字段 | 样例导出列 | 目标列 |
| --- | --- | --- | --- |
| 副驾驶阶段经历时间 | 飞行经历 | O | 副驾驶进度 F |
| 副驾驶阶段起落数 | 起落总数 | V | 副驾驶进度 G |
| 一二检左座经历 | 左座经历 | R | 一二检进度 F |
| 一二检起落数 | 起落总数 | V | 一二检进度 G |

1. 先按「输入员工号+输入开始日期+输入结束日期」唯一匹配；再核输入姓名、查询状态成功、返回工号/姓名及返回日期窗口。返回结果行顺序可以变化，不能按位置或只按姓名硬贴。
2. 缺人、同窗口重复、查询失败、姓名冲突、返回窗口不符均列异常；未核清前不把这批结果写成完整已更新。导出多出的窗口单列，不能写进不在本轮名单的行。
3. 只取上表指定字段。「飞行时间」「副驾驶经历」「起飞次数/落地次数」均不是本任务替代字段；起落总数不把起飞和落地相加，不把新结果累加到旧值。
4. 本次验证的去分钟版字段为整数或数字文本，写回非负数值型整数，零也要正常写入。若给的是 HH:MM 或小数小时，先确认/取得去分钟版，不擅自截断、四舍五入或按小数小时换算。
5. 源表自生成查询后有变动时，重新核名单、窗口和变更；不要拿旧本轮记录强写新名单。重新核验不能满足时告知主人缺什么。
6. 先输出逐项拟改清单，再备份并校验备份一致；备份失败停止。保留全表工作表、样式、公式、数据验证及无关内容。只写所选来源行 F/G，不改阶段、检查日期、资格、更新标题和其他 sheet。
7. 核验全部目标指标值与导出一致、无关单元格与原表一致、公式仍在。最终只交付一份更新后的实力表，聊天简报关键人数和变化格数，不额外交付核对报告、备份或试填版本。

## 最终交付与过程清理

1. 最终文件名沿用原实力表主名，加「（由皮燕子更新副驾驶和一二检数据截止YYYY-MM-DD）.xlsx」。例如：南货航飞行实力表20261023（由皮燕子更新副驾驶和一二检数据截止2026-10-23）.xlsx。日期取本轮查询截止日；Windows文件名不能用斜杠，使用连字符。
2. 主人提供的原始实力表、模板、导出结果和其他资料全部保留，不覆盖、不删除。默认从原表生成独立最终副本；原表本身保留原始内容，无需再留重复备份。
3. 第一步查询表与本轮记录在等待主人跑查询期间保留；回填校验成功、最终版就位后，清理皮燕子本轮生成的查询表、记录、核对报告、试填副本和重复备份，最终业务成果只剩一份。仅删除可明确辨认由本轮生成的过程文件，不按通配符扫删主人资料。
4. 预检或回填失败时先保留诊断所需文件并说明问题，不把未完成文件冒充最终版。明确要求原地覆盖时仍先备份；默认独立副本交付。

## 仓库辅助脚本

脚本仅作辅助，一切从本轮真实表格出发。每次先只读调研原表、查询模板与导出的工作表、表头、实际列位置、分块、日期格式、公式和目标格，再决定脚本是否适用。本文中的列号和历史人数仅为已验证样例，不能覆盖本轮实表；发现结构变化时先调整映射、核对副本，不得直接套旧模板实写。业务含义以主人已确认的口径为准，含义不明时问清。

`scripts/update_progress.py`（依赖 openpyxl）提供 `prepare` 和 `apply`；先用 `--help` 看参数。脚本服务本仓工作流；仅下载本篇 Markdown 时可据上述规则实现，不能因本机找不到脚本跳过核验。

```
python scripts/update_progress.py prepare --source "本轮实力表.xlsx" --end YYYY-MM-DD --captain-scope first-block --output "本轮查询.xlsx" --session "本轮记录.json"
python scripts/update_progress.py apply --session "本轮记录.json" --export "主人导出_去分钟版.xlsx"
```

`prepare` 默认 `--template` 指向 `templates/飞行经历查询（皇帝版）-模板.xlsx`；仅当主人另给空模板路径时再显式传入。`first-block` 按第二表头截断；`all` 只在主人明确要求包含下一块时使用。`apply --preview` 只预检；`--report` 可选，默认不生成独立报告；`--output` 默认按上述规则命名最终版。默认保留原表、另存唯一最终副本；明确要求原地覆盖才把 `--output` 设为原路径并先备份。Agent成功核验后按「最终交付与过程清理」清理本轮生成的过程文件；脚本不自动删输入；仓内空模板始终保留。
